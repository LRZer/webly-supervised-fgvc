# 网络监督细粒度图像分类

[English](README.md) · [算法细节](docs/METHODS.md) · [运行指南](docs/REPRODUCIBILITY.md) · [证据与历史](docs/EVIDENCE.md)

面向 **WebFG-400** 和 **WebiNat-5000** 的图像分类项目：检查网络图像的可用性，按类别计算特征一致性，筛选疑似异常样本，微调基于 ImageNet-1K 预训练的 ConvNeXt-Base，并生成比赛预测文件。

任务是从外观相近的飞机、汽车、鸟类或自然物种中识别具体子类别。网络训练图像的标签可能有误，因此项目在监督训练前加入文件检查和基于视觉特征的样本筛选。

仓库包含找回的原始代码和预测数据、可配置的运行版本、课程报告及技术说明。**下列准确率来自历史报告，本次整理未在比赛数据集上重新训练。**

### 0. 数据与权重准备

训练数据按 `<数据根目录>/<类别编号>/<图像文件>` 存放，类别文件夹名称就是训练标签；每类图像直接放在该类别目录下。测试集为平铺目录，保留赛事原始文件名。两个任务分别处理、分别训练，不能混用类别映射。

原图保存在 `data/raw/`，另复制一份到 `data/working/` 执行清洗。需要准备两种 **ImageNet-1K 预训练权重**：DeiT III 用于提取筛选特征，ConvNeXt-Base 用于初始化最终分类器。前者不参与最终测试预测，后者也不使用前者的模型参数。目录示例及权重文件名见[数据说明](data/README.md)。

### 1. 基础清洗：检查图像是否能作为模型输入

递归收集工作目录中的图像，多进程逐张检查。任何一项规则触发，就记录为筛除候选：

| 检查 | 默认规则 | 判断方法 |
|---|---|---|
| 文件大小 | 小于 10,240 字节（10 KiB） | 先读取文件大小，过小文件不再解码 |
| 可解码性 | PIL 无法打开或完整加载 | 实际解码，而非仅检查扩展名 |
| 图像尺寸 | 最短边小于 64 像素 | 解码后读取宽高，计算 `min(宽,高)` |
| 透明像素 | PNG/GIF 中非全透明像素占比小于 5% | 转 RGBA，统计 `alpha > 0`；大图降采样，GIF 检查首帧 |

整理版默认预演，仅输出命中的路径和原因。加 `--apply` 后，先按相对路径复制到独立备份目录，复制成功才从工作目录移除。`phase1_removed.csv` 记录源路径、备份路径、原因和字节数。后续特征提取读取清洗后的工作目录。

这些规则处理文件可用性，不能判断类别标签是否正确；文件大小阈值也可能命中正常的高压缩图像。

### 2. 特征提取：为每张图像建立视觉表示

1. 按类别和文件路径排序收集图像，将图像转为 RGB；解码失败的图像跳过，并写入 `phase2_bad_images.csv`。
2. 双三次插值将短边缩放到 **256**，中心裁剪为 **224 × 224**。像素转为 0–1 范围的张量后，按 ImageNet 通道均值 `(0.485, 0.456, 0.406)`、标准差 `(0.229, 0.224, 0.225)` 标准化。
3. 严格加载本地 `deit3_base_patch16_224.fb_in1k` 权重，移除 1,000 类分类头。模型保持评估模式，不更新参数，每张图像输出一条特征向量。
4. 对向量做 L2 归一化，即除以自身长度，使后续比较使用向量方向。默认以 float16 保存；评分时转换为 float32 并再次归一化。

**DeiT III Base 内部结构。** 224 × 224 图像按 16 × 16 分块，得到 14 × 14 = **196 个图像块**，每块投影为 768 维向量并加入位置信息。在序列开头加入一个可学习的 CLS 汇总向量，共 197 个 token，经过 **12 个 Transformer 模块**；每个模块包含 LayerNorm、12 头自注意力，以及 `768 → 3072 → 768` 的前馈网络，两条分支均使用 LayerScale 和残差连接。自注意力让不同图像块交换信息；最终取归一化后的 CLS 向量作为整张图的 **768 维特征**，而不是对 196 个块直接取平均。结构依据 [timm 1.0.12 的 DeiT 实现](https://github.com/huggingface/pytorch-image-models/blob/v1.0.12/timm/models/deit.py)及其 [Transformer 实现](https://github.com/huggingface/pytorch-image-models/blob/v1.0.12/timm/models/vision_transformer.py)。

产物 `features.npy` 是 **M × D** 矩阵：M 为成功读取的图像数，D 为特征维度；默认模型 D = 768。`index.csv` 的第 i 行记录矩阵第 i 行对应的路径、类别 ID 和类别名，不能单独重排其中一个文件。这一阶段只生成筛选特征，最终分类器在**筛选后的图像**上训练，不读取这些缓存向量。

### 3. 一致性评分：按类识别低一致性样本

评分只在同一类别内比较，不把不同类别的绝对分数混在一起排名。先检查特征与索引行数一致、没有重复路径或非有限数值，再逐类计算：

1. **类中心分数 s₁**：同类特征取均值后归一化，再计算每张图像与类中心的余弦相似度，衡量其是否接近本类整体外观。中心计算包含图像自身。
2. **邻居分数 s₂**：计算类内两两余弦相似度，排除自身，取最相似的 10 张图像的平均值，衡量其是否有相近的同类样本。其他样本不足 10 张时全部使用；只有一张图时该分数为 0。
3. **综合分数**：`S = 0.7 × s₁ + 0.3 × s₂`。对每类独立求 S 的第 10、25 百分位点 P₁₀、P₂₅，并分组：

| 分组 | 条件 | 默认处理 |
|---|---|---|
| `gray` | S < P₁₀ | 进入移除候选 |
| `low` | P₁₀ ≤ S < P₂₅ | 保留 |
| `clean` | S ≥ P₂₅ | 保留 |

4. **限制移除数量**：只从 `gray` 中按 S 从低到高选择，每类配额为 `max(0, min(候选数, floor(0.15 × 类别图像数), 类别图像数 − 30))`。因此 15% 是上限，不是固定删除比例；30 张及以下的类别不移除。少于 10 张时 P₁₀ 使用最小值，少于 4 张时 P₂₅ 使用顺序统计回退；同分样本也可能没有 `gray` 候选。

输出 `sample_score.csv`（逐图 s₁、s₂、S、分组）、`class_thresholds.json`（各类阈值与均值）、`kept_list.csv`、`removed_list.csv`。**此脚本不修改图像文件**。分组是相对一致性判断，不等于已确认错标。算法构建每类完整相似度矩阵，m 张图像需要 O(m²) 存储；完整公式见[算法说明](docs/METHODS.md)。

### 4. 审核与移除：将清单落实到工作目录

先读取 `removed_list.csv`，按原有类别层级复制候选图像到独立审核目录；结合评分表生成 `class_remove_stats.csv`，记录每类总量、候选数量和候选比例，可据此检查哪些类别受到影响。

复制操作本身不会减少训练图像。检查候选后，用 `--delete` 单独从工作目录移除清单中的文件；默认逐张检查审核副本是否存在，无副本则跳过，并报告成功、跳过和缺失数量。下一阶段对实际剩余图像划分。若仅生成评分清单或审核副本就直接划分，候选图像仍会进入训练或验证集。

脚本提供人工查看入口，但恢复材料没有完整复核记录，不能据此声称所有候选已经人工确认。

### 5. 数据划分：逐类建立训练集与验证集

对净化后每个类别的文件先排序，再用种子 **2025** 随机打乱。n > 1 时，默认验证数量为 `min(n − 1, max(1, round(0.15 × n)))`，取打乱后的前若干张作为验证集，其余作为训练集。每类至少留一张训练图；只有一张的类别全部用于训练，因此总体比例约为 **85/15**。

默认复制到新的空目录 `train/<类别>/`、`val/<类别>/`。整理版另存 `split_manifest.csv`，逐图记录来源、所属集合、类别和文件名，用它确认实际划分，而不是仅依赖随机种子。训练前检查 train/val 的类别映射一致，且分别符合 400 类或 5,000 类任务。

验证集用于选择模型权重。原流程先净化再划分，净化已使用后来进入验证集的图像特征；它不能独立测量净化步骤的收益。源码也没有图像内容去重，重复图像可能跨集合。

### 6. 分类训练：微调 ConvNeXt-Base

**模型初始化。** 严格加载 `convnext_base.fb_in1k` 的 1,000 类预训练权重，再将分类头替换为 400 类或 5,000 类输出；整个网络参与训练。四个特征阶段的通道数为 `[128, 256, 512, 1024]`，模块数量为 `[3, 3, 27, 3]`。最后的特征经过全局平均池化和归一化，得到 1,024 维表示，再由线性分类头输出各类别分数。

![DeiT III 特征提取器与 ConvNeXt-Base 分类器结构](docs/assets/architecture.png)

**尺寸如何变化。** B 表示批次大小，下表采用 `B × 通道 × 高 × 宽` 记法；空间尺寸逐步减半，通道数增加：

| 位置 | 处理 | 输出尺寸（320 × 320 输入） |
|---|---|---|
| 输入 | RGB 图像 | B × 3 × 320 × 320 |
| Stem | 4 × 4 卷积，步长 4；LayerNorm | B × 128 × 80 × 80 |
| Stage 1 | 3 个 ConvNeXt 模块 | B × 128 × 80 × 80 |
| Stage 2 | LayerNorm + 2 × 2、步长 2 卷积；3 个模块 | B × 256 × 40 × 40 |
| Stage 3 | 同类降采样；27 个模块 | B × 512 × 20 × 20 |
| Stage 4 | 同类降采样；3 个模块 | B × 1024 × 10 × 10 |
| 分类头 | 全局平均池化 → LayerNorm → 线性层 | B × 400 或 B × 5000 |

**一个 ConvNeXt 模块如何工作。** `7 × 7 逐通道卷积 → LayerNorm → 线性扩展 C→4C → GELU → 线性压缩 4C→C → LayerScale → DropPath → 加回输入`。逐通道卷积在每个通道内提取空间信息，两个线性层在同一位置混合通道；LayerScale 用可学习系数调节分支输出，残差连接保留输入信息。模块内部保持空间尺寸，降采样发生在阶段入口。这里使用 **ConvNeXt V1 Base**，没有 V2 的 GRN 模块。结构依据 [timm 1.0.12 的 ConvNeXt 实现](https://github.com/huggingface/pytorch-image-models/blob/v1.0.12/timm/models/convnext.py)。

**图像增强与训练目标。** 训练和验证采用不同预处理，均使用阶段 2 的 ImageNet 均值/标准差：

| 用途 | 操作 | 作用 |
|---|---|---|
| 训练 | 随机缩放裁剪到 320 × 320；RandAugment 每次 2 个操作、强度 7；随机水平翻转；张量标准化后以 0.25 概率随机擦除 2%–20% 面积 | 改变可见区域、外观与局部遮挡 |
| 验证 | 短边缩放到 `int(320 × 1.14) = 364`，中心裁剪到 320 × 320，再标准化 | 用固定预处理比较各轮模型 |

每个训练批次由 Mixup 或 CutMix 处理，二者切换概率为 0.5。Mixup 按比例混合两张图像和标签；CutMix 替换局部区域，并按实际区域面积混合标签。下表的 alpha 控制混合比例的采样分布。训练使用软标签交叉熵，即按混合比例学习两个类别；标签平滑为 0。验证不混合样本，使用原类别标签计算普通交叉熵和准确率。

**每个批次的计算。** `读取并增强图像 → Mixup/CutMix → 前向计算类别分数 → 计算损失 → 反向传播梯度 → AdamW 更新参数 → 更新 EMA`。每张图的损失为 `L = −Σ qₖ log softmax(logits)ₖ`，qₖ 是混合后的目标类别比例，批次内取平均；损失通过反向传播更新分类头及骨干网络。训练加载器打乱样本并丢弃不足一批的尾部；无法解码的图像被跳过，若使 Mixup 批次变为奇数，整理版再去掉一张以满足成对混合要求。日志中的实际处理数量因此可能少于目录图像总数。

**优化与模型选择。** AdamW 更新全部参数，前 3 轮学习率从基准值的 20% 线性预热，之后按余弦曲线下降至 0.000001。配置中的 Drop path 0.4 是最大丢弃概率，按模块深度从 0 线性增加至 0.4，评估时关闭。每次成功更新参数后，同步维护 EMA：`EMA新值 = 0.9999 × EMA旧值 + 0.0001 × 当前参数`，用于平滑连续更新。

每轮结束，用 EMA 模型遍历验证集，以“预测正确图像数 / 成功读取的验证图像数”计算准确率；高于此前最优值时保存 `best.pth`。CUDA 下使用混合精度、梯度缩放和 TF32；整理版对模型及输入使用 channels-last 内存布局。

| 找回代码的训练参数 | WebFG-400 | WebiNat-5000 |
|---|---:|---:|
| 模型 | `convnext_base.fb_in1k` | `convnext_base.fb_in1k` |
| 输入 / 批次大小 | 320 × 320 / 64 | 320 × 320 / 64 |
| 训练轮数 | 100 | 50 |
| Mixup alpha / CutMix alpha | 0.2 / 0.2 | 0.4 / 1.0 |
| AdamW 学习率 / 权重衰减 | 0.0005 / 0.05 | 0.0005 / 0.05 |
| 预热 / 最低学习率 | 3 轮 / 0.000001 | 3 轮 / 0.000001 |
| 最大 Drop path / EMA 衰减 | 0.4 / 0.9999 | 0.4 / 0.9999 |

**训练产物。** 原脚本保存最优 EMA 权重和类别映射，整理版补充最后一轮权重与运行记录：

| 文件 | 含义与用途 |
|---|---|
| `best.pth` | 验证准确率最高的 EMA 权重，用于测试推理 |
| `classes.txt` | `模型输出索引 → 类别文件夹名`；必须与权重配套保存 |
| `last.pth`（新增） | 最后一轮 EMA 权重 |
| `last_raw.pth`（新增） | 最后一轮普通模型权重 |
| `run_config.json`（新增） | 实际参数、数据路径、权重来源及运行模式 |
| `history.csv`（新增） | 逐轮学习率、训练/验证损失、验证准确率、实际处理数量和耗时 |

加载已有任务权重可使用 `--init-weights` 继续训练，并另设轮数、学习率和预热参数；该方式新建优化器、调度器和 EMA，不恢复原优化器或随机状态。完整命令见[运行指南](docs/REPRODUCIBILITY.md)。

### 7. 测试推理：从模型输出生成比赛 CSV

1. 加载任务 `best.pth` 和配套 `classes.txt`，构建相同类别数的 ConvNeXt-Base，严格检查权重是否匹配。映射文件保留训练时的类别顺序，不能直接假定输出索引就是比赛编号。
2. 按文件名排序读取平铺测试目录，转 RGB，使用与验证相同的 **364 短边 → 320 × 320 中心裁剪 → 标准化**，在评估模式下前向计算。
3. 若启用 `--tta`，同一模型再预测水平翻转的裁剪图，对两次原始类别分数（logits）取平均后选最高分。未启用时只预测一次；现有历史 CSV 无法判断当时是否启用 TTA。
4. 将最高分的输出索引查表得到类别名，再补零为四位数字。逐行写出 `图像文件名,类别编号`，无表头，无完整路径。

默认发现无法解码的测试图像时拒绝写出不完整 CSV，防止图像被静默遗漏。TTA 使用同一套分类器权重，增加的是输入视角。

### 8. 输出校验与成绩解释

整理版校验工具检查每行恰好两列、文件名不含路径、类别为四位数字且在任务范围内、没有重复文件名。提供 `--expected-rows` 时核对记录数；提供 `--test-root` 时比较 CSV 和实际测试目录的文件名集合，检查漏项和多项。

这些检查只确认输出格式与覆盖。测试准确率需要真实标签，计算为 `预测正确图像数 / 测试图像总数`；赛题按同一 A/B 阶段两个任务准确率的平均值计分。仓库没有测试真实标签或官方评分回执，因此不能从两份预测 CSV 重算报告准确率、混淆矩阵或 F1。

## 使用方法

用 Python 3.11 即可检查仓库内的预测文件，无需安装机器学习依赖：

```bash
python scripts/validate_predictions.py results/predictions/pred_results_web400.csv --num-classes 400 --expected-rows 5687
python scripts/validate_predictions.py results/predictions/pred_results_web5000.csv --num-classes 5000 --expected-rows 60000
```

运行数据处理、训练或推理前，安装整理版环境：

```bash
python -m venv .venv
# 按当前终端的方式激活 .venv 后：
python -m pip install -r requirements.txt
```

完成图像目录准备并取得对应的本地预训练权重后，可训练 400 类任务：

```bash
python scripts/train.py --config configs/webfg400.json --data-root data/working/webfg400_split --out-dir experiments/webfg400 --pretrained-checkpoint data/weights/convnext_base.fb_in1k.safetensors
```

[运行指南](docs/REPRODUCIBILITY.md)提供所有处理阶段、两个任务、推理、仅加载权重继续训练及 CPU/GPU 环境的完整命令。[模型卡](https://huggingface.co/timm/convnext_base.fb_in1k)说明 ImageNet-1K 预训练来源；恢复实验时仍需核对本地权重文件。
